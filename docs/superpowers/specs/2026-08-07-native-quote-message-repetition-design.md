# Native Quote-Message Repetition Design

## Goal

Make `RepeatMessages` preserve type-57 WeChat quote messages instead of reducing them to plain text. Add a convenient reusable API for sending text that quotes a message identified by server ID, while preferring WeChat's native quote-send path.

The change must support at least the supplied cases:

- a group message whose reply text quotes another text message;
- a group message whose reply text quotes an image message with nested escaped image XML.

Supported WeChat versions remain 8.0.65–8.0.77.

## Current behavior

`RepeatMessages.repeatMessage` handles `MessageType.QUOTE` by calling `WeMessageApi.sendText` with `quoteMsgActualContent`. This preserves only the outer reply text and discards the quoted-message relationship.

`MessageInfo.QuoteMessage` already exposes the stored quote's outer title and embedded reference fields, including `svrid`, type, sender data, message source, and content.

`WeMessageApi` has older quote helpers that build type-57 data in WeKit. The new API should instead follow WeChat's native quote-send builder so WeChat owns type mapping, source metadata, serialization, outgoing ownership, and message insertion.

## Native behavior established from WeChat sources

WeChat's ChatFooter creates a fresh type-57 native app-message object for a quote send. It sets the entered reply text as the title and populates a fresh `MsgQuoteItem` from the referenced stored message. The same structure appears throughout the inspected 8.0.65–8.0.76 sources.

WeChat's `MsgRetransmitUI` handles an existing type-57 message differently from generic raw AppMsg forwarding. It parses the stored message to obtain the outer title, then invokes the native text/quote builder with:

- destination talker;
- outgoing title;
- source message local ID;
- source message talker.

The builder reloads the source type-57 message and preserves its embedded reference while generating a fresh outgoing envelope. It does not retransmit the stored XML verbatim.

Consequently, fields such as `fromusername`, `scene`, `appinfo`, `commenturl`, outer message source, local/server IDs, timestamp, status, destination, and current-user ownership must be generated by the native sender. They must not be copied or edited manually. The embedded `refermsg` fields continue to identify the referenced message and must remain intact.

Relevant source evidence includes:

- 8.0.65 ChatFooter quote construction: `wechat_8065/app/src/main/java/com/tencent/mm/pluginsdk/ui/chat/ChatFooter.java:1176-1269`
- 8.0.76 ChatFooter quote construction: `wechat_8076/app/src/main/java/com/tencent/mm/pluginsdk/ui/chat/ChatFooter.java:1560-1656`
- 8.0.65 type-57 retransmit: `wechat_8065/app/src/main/java/com/tencent/mm/ui/transmit/MsgRetransmitUI.java:2804-2853`
- 8.0.76 type-57 retransmit: `wechat_8076/app/src/main/java/com/tencent/mm/ui/transmit/MsgRetransmitUI.java:2206-2251`
- 8.0.65 quote parsing: `wechat_8065/app/src/main/java/do0/q.java:1031-1045`
- 8.0.76 quote parsing: `wechat_8076/app/src/main/java/pt0/r.java:1167-1180`

There is no local 8.0.77 decompiled tree. Compatibility for 8.0.77 must therefore be validated with the project's desktop Dex resolver rather than claimed from source inspection.

## Architecture

### Reusable quote API

`WeMessageApi` will expose:

```kotlin
fun sendQuoteText(
    talker: String,
    quotedMsgSvrId: Long,
    content: String,
): Boolean
```

The function will:

1. Resolve the referenced stored message using `talker` and `quotedMsgSvrId`.
2. Invoke WeChat's native text/quote builder with the destination, outgoing content, referenced message local ID, and referenced message talker.
3. Execute the native send request.
4. Log failures and return `false`, consistent with other public send APIs.

The public contract uses `Long` because WeChat server IDs in the supplied messages exceed 32-bit integer range.

The API does not accept, parse, or reconstruct original quote XML. It depends on the referenced message still being locally available.

### Local-ID native quote helper

`WeMessageApi` will also expose:

```kotlin
fun sendQuoteTextByMsgId(
    talker: String,
    quotedMsgId: Long,
    content: String,
): Boolean
```

This is the local-ID form of the same native operation. For an ordinary source message it sends text quoting that source. For an existing type-57 source, WeChat reloads the quote message, preserves its embedded `MsgQuoteItem`, and creates a fresh outgoing quote. This matches `MsgRetransmitUI` and provides the fallback needed by `RepeatMessages` without requiring a live `Activity`, `ChatFooter`, or `ChattingContext`.

The existing `sendQuoteMsgByMsgId` and `sendQuoteMsgByMsgSvrId` entry points will become compatibility aliases for these native implementations. The unused overload that accepts `referContent` and manually constructs quote metadata will be removed; no caller should supply hand-built reference content to the native API.

### `RepeatMessages` orchestration

For a `MessageType.QUOTE` message A:

1. Parse A with `msgInfo.toQuoteMessage()`.
2. Use A's outer title as the outgoing reply text.
3. Call `sendQuoteText(msgInfo.talker, quote.svrid, quote.title)`.
4. If that succeeds, repetition is complete.
5. If it returns `false`, call `sendQuoteTextByMsgId(msgInfo.talker, msgInfo.id, quote.title)`.
6. Return the fallback result.

The fallback decision remains in `RepeatMessages`. `sendQuoteText` does not know about A or its original XML.

## Data flow

```text
Repeat quote A
    |
    +-- parse A.title and A.refermsg.svrid
    |
    +-- sendQuoteText(talker, referenced server ID, A.title)
    |       |
    |       +-- referenced message found: native quote send succeeds
    |       |
    |       +-- referenced message unavailable: returns false
    |
    +-- fallback: native retransmit using A's local ID and talker
            |
            +-- WeChat reloads A
            +-- WeChat preserves A's embedded refermsg
            +-- WeChat generates a fresh outgoing envelope
```

For the quoted-image sample, the escaped image document remains inside `refermsg.content`. It is never promoted to an outer thumbnail or manually parsed and rebuilt by WeKit.

## Dex resolution

The implementation will resolve the native text/quote builder and execution path using stable structural evidence from the inspected versions, not obfuscated names. Candidate matchers should use distinctive builder call sites, signatures, constants, and/or strings verified across supported APKs.

Resolver code must follow the project's desktop-safe rules:

- use delegate `.data` metadata inside resolution;
- avoid host JVM reflection while resolving;
- use `DexResolutionContext.host` for any version branches;
- do not mark required, universally present quote-send targets with `allowFailure`;
- do not loosen matcher constraints simply to make a test pass.

The existing manually constructed quote helpers may remain for compatibility unless their replacement is necessary to avoid conflicting semantics. Any API whose parameter is named `msgSvrId` must call the server-ID path rather than the local-ID path.

## Failure behavior

- Referenced message available and native quote send succeeds: return success.
- Referenced-message lookup or primary native send fails: `RepeatMessages` tries native retransmit from the existing quote message.
- Existing quote message cannot be reloaded or retransmitted: return failure and keep the existing `复读失败!` toast.
- Do not fall back to plain text.
- Do not fall back to hand-built AppMsg XML.
- Log the primary and fallback failures sufficiently to distinguish the two paths.

## Scope

Included:

- native quote-text API in `WeMessageApi`;
- native local-ID quote helper, including existing-quote retransmission;
- quote-preserving `RepeatMessages` routing;
- correction of directly related server-ID/local-ID mismatches encountered in callers of the quote API;
- Dex resolver validation for affected declarations.

Excluded:

- changing generic `ForwardMessages` quote behavior;
- supporting new quoteable message types beyond what WeChat's native builder accepts;
- manually rebuilding `refermsg` or outer AppMsg XML;
- UI changes;
- adding low-value JVM tests around host-dependent reflection or WeChat behavior.

## Validation

This work is host/DexKit integration and does not qualify for isolated JVM TDD under the project testing policy.

Validation will include:

1. Run `./x dex-test` for every supported WeChat APK affected by the new resolver declarations, including normal and Google Play variants when available, across 8.0.65–8.0.77.
2. Run relevant existing qualifying Gradle tests if any changed WeKit-owned core logic has such tests.
3. Run `./x build`.
4. Run `git diff --check`.
5. Manually test in WeChat:
   - repeat a quote of a text message while the referenced message exists;
   - repeat a quote of an image while the referenced message exists;
   - remove or otherwise make the referenced message unavailable, then verify native retransmit from the existing quote still preserves the reference;
   - confirm the repeated message is owned by the current user and has a newly generated outer envelope;
   - confirm tapping the quoted portion resolves as expected when its referenced message remains available.

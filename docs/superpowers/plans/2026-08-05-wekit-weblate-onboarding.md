# WeKit Hosted Weblate Libre Onboarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the stabilized English/Simplified/Traditional Android catalog to Hosted Weblate Libre with reviewed community translation, a protected service-branch pull-request workflow, GPLv3 contribution terms, and durable translator credits.

**Architecture:** Keep GitHub `dev` authoritative, let Weblate fetch `dev` and push only `weblate/dev`, and merge translation changes through normal reviewed pull requests. Repository documentation, glossary, CI, and credits are prepared before the external component is opened; account/application and repository-write actions stop for explicit maintainer authorization because they modify external state.

**Tech Stack:** Hosted Weblate Libre, GitHub branches/pull requests, Android string resources, OpenCC `s2t`, Markdown documentation, existing WeKit About UI

## Global Constraints

- Complete and verify both `2026-08-05-wekit-i18n-foundation.md` and `2026-08-05-wekit-i18n-catalog-migration.md` first.
- GitHub `dev` is the source branch and source of truth.
- English source is `app/src/main/res/values/strings.xml`.
- Targets are exactly `values-zh-rCN/strings.xml` and `values-zh-rTW/strings.xml`.
- Weblate pushes only `weblate/dev`; it never pushes or force-pushes `dev`.
- Translation pull requests use regular merge commits, not squash or rebase.
- Weblate never auto-merges a pull request.
- Community users suggest; trusted translators translate; language reviewers approve; maintainers merge.
- Traditional Chinese generated by OpenCC remains unapproved until human review.
- Translation contributions are distributed under the repository's GPLv3 license; do not add a separate CLA.
- Do not run Crowdin or another translation platform in parallel.
- Do not perform account creation, hosting application submission, token/deploy-key creation, branch push, or Weblate component mutation without explicit maintainer authorization at the external-state checkpoint.

## File Map

- Create `docs/translations/README.md`: contributor workflow, source/target ownership, string rules, review and Git flow.
- Create `docs/translations/GLOSSARY.md`: canonical terminology for English, Simplified Chinese, and Traditional Chinese.

- Modify `README.md`: translation contribution link and Hosted Weblate attribution badge/link.

- Modify the three Android string files for About-row text.
- Modify `.github/PULL_REQUEST_TEMPLATE.md`: translation-specific review checklist.
- External: Hosted Weblate project `wekit`, component `android-app`, GitHub service branch `weblate/dev`.

- [ ] **Step 1: Write the translation contribution guide**

Create `docs/translations/README.md` with these concrete sections:

1. Supported languages: English source, Simplified Chinese, Traditional Chinese.
2. English source ownership: developers edit default `values/strings.xml` in code PRs.
3. Community workflow: translators use Hosted Weblate; direct XML PRs are accepted only when

5. String rules: semantic keys, indexed placeholders, plurals, markup, comments,
   `translatable="false"`, no concatenated sentence fragments.

   preference/cache keys, URLs, package names, and scripting identifiers.
7. Review flow: suggestions, trusted translators, language reviewers, maintainer merge.
8. Git flow: `dev` source, `weblate/dev` service branch, regular merge commits, no automatic merge.
9. Validation commands:

```bash
./x i18n-check
./x build
git diff --check
```

10. License statement: submitted translations become GPLv3 project contributions.
11. Credit policy: accepted contributors may add their preferred public name/profile to
    `TRANSLATORS.md`; no private email is required.
